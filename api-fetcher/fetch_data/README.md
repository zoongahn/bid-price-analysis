# fetch_data - 나라장터 공공데이터 수집 시스템

공공데이터 포털의 나라장터 Open API를 통해 데이터를 수집하고 MongoDB에 저장하는 시스템입니다.

---

## 📁 디렉토리 구조

```
fetch_data/
├── README.md                # 이 파일
├── main.py                  # CLI 실행 진입점
├── src/
│   ├── data_collector.py    # 핵심 수집 오케스트레이터
│   ├── api_client.py        # HTTP 통신 (SSL/TLS 처리, 재시도 로직)
│   ├── params_builder.py    # API 요청 파라미터 생성
│   ├── mongo_writer.py      # MongoDB upsert 처리
│   ├── record_writer.py     # 수집 기록 파일 관리
│   ├── api_info.py          # API 메타정보 조회 (gfcon.api_list)
│   └── missing_company_collector.py  # 누락 company 증분 수집
├── py_scripts/              # 유틸리티 스크립트
└── test*.py                 # 테스트 파일
```

## 🎯 핵심 개념

### API 계층 구조

나라장터 Open API는 **서비스 > 오퍼레이션** 2단계 구조입니다:

```
서비스 (Service)
├── 입찰공고정보서비스
├── 낙찰정보서비스
├── 사용자정보서비스
├── 공공데이터개방표준서비스
└── 계약정보표준서비스

오퍼레이션 (Operation)
├── 입찰공고목록정보에대한공사조회 (일련번호: 1)
├── 입찰공고목록정보에대한공사기초금액조회 (일련번호: 6)
└── ...
```

### MongoDB 데이터베이스 구조

데이터는 용도에 따라 두 개의 데이터베이스로 분리됩니다:

```
MongoDB
├── gfcon           # 메타데이터
│   └── api_list    # API 서비스/오퍼레이션 정의
│
└── gfcon_raw       # 수집된 원본 데이터
    ├── 입찰공고정보서비스.입찰공고목록정보에대한공사조회
    ├── 입찰공고정보서비스.입찰공고목록정보에대한용역조회
    ├── 입찰공고정보서비스.입찰공고목록정보에대한외자조회
    ├── 입찰공고정보서비스.입찰공고목록정보에대한물품조회
    ├── 입찰공고정보서비스.입찰공고목록정보에대한공사기초금액조회
    ├── 입찰공고정보서비스.입찰공고목록정보에대한물품기초금액조회
    ├── 입찰공고정보서비스.입찰공고목록정보에대한용역기초금액조회
    ├── 공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-공사
    ├── 공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-물품
    ├── 공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-외자
    ├── 공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-용역
    ├── 사용자정보서비스.조달업체기본정보
    └── ...
```

### MongoDB 컬렉션 명명 규칙

수집된 raw 데이터는 `{서비스명}.{오퍼레이션명}` 형식으로 `gfcon_raw` 데이터베이스에 저장됩니다.

**예외: 공공데이터개방표준서비스의 낙찰정보**

`공공데이터개방표준서비스`의 `데이터셋개방표준에따른낙찰정보`는 사업구분코드(bsns_div_cd)별로 분리하여 저장됩니다:

| bsns_div_cd | 사업구분 | 컬렉션명 |
|-------------|---------|---------|
| 1 | 물품 | `공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-물품` |
| 2 | 외자 | `공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-외자` |
| 3 | 공사 | `공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-공사` |
| 5 | 용역 | `공공데이터개방표준서비스.데이터셋개방표준에따른낙찰정보-용역` |

### API 메타정보 (gfcon.api_list)

각 서비스/오퍼레이션의 메타정보는 MongoDB `gfcon.api_list` 컬렉션에 저장되어 있습니다:

## 🚀 사용법

### CLI 실행

```bash
cd /data/dev/bid-price-analysis/api-fetcher

# 특정 기간 수집
python -m fetch_data.main \
  --service "입찰공고정보서비스" \
  --oper 1 \
  --start-date 2024-01-01 \
  --end-date 2024-12-31

# 특정 연도 전체 수집
python -m fetch_data.main \
  --service "공공데이터개방표준서비스" \
  --oper 1 \
  --year 2024

# 사업구분별 수집 (공공데이터개방표준서비스)
python -m fetch_data.main \
  --service "공공데이터개방표준서비스" \
  --oper 2 \
  --year 2024 \
  --bsns-div 3  # 공사 (기본값)

python -m fetch_data.main \
  --service "공공데이터개방표준서비스" \
  --oper 2 \
  --year 2024 \
  --bsns-div 1  # 물품

python -m fetch_data.main \
  --service "공공데이터개방표준서비스" \
  --oper 2 \
  --year 2024 \
  --bsns-div 5  # 용역

# 인터랙티브 모드 (서비스/오퍼레이션 선택)
python -m fetch_data.main
```

### CLI 옵션

| 옵션 | 설명 | 예시 |
|------|------|------|
| `--service` | 수집할 서비스명 | `"공공데이터개방표준서비스"` |
| `--oper` | 오퍼레이션 일련번호 | `2` |
| `--year` | 수집할 연도 | `2024` |
| `--start-date` | 수집 시작 날짜 | `2024-01-01` |
| `--end-date` | 수집 종료 날짜 | `2024-12-31` |
| `--bsns-div` | 사업구분코드 (1=물품, 2=외자, 3=공사, 5=용역) | `3` (기본값) |

### 프로그래매틱 사용

```python
from fetch_data.src.data_collector import DataCollector

# 날짜 범위 수집
collector = DataCollector(
    service_name="입찰공고정보서비스",
    operation_number=1,
    start_date="2024-01-01",
    end_date="2024-01-31"
)
collector.execute()

# 사업구분별 수집 (물품/외자/공사/용역)
collector = DataCollector(
    service_name="공공데이터개방표준서비스",
    operation_number=2,
    year="2024",
    bsns_div_cd=1,  # 1=물품, 2=외자, 3=공사, 5=용역
)
collector.execute()

# 특정 공고번호로 수집 (PK 방식)
collector = DataCollector(
    service_name="입찰공고정보서비스",
    operation_number=1
)
collector.collect_notice_by_NtceNo(["20240101001", "20240101002"])

# 특정 사업자등록번호로 수집 (PK 방식)
collector.collect_company_by_bizno(["1234567890", "0987654321"])
```

## ⚙️ 핵심 컴포넌트

### 1. DataCollector (data_collector.py)

수집 프로세스의 중앙 오케스트레이터입니다.

**주요 메서드:**

| 메서드 | 설명 |
|--------|------|
| `execute()` | 설정에 따라 적절한 수집 방식 자동 선택 |
| `collect_data_by_day(date)` | 특정 날짜의 데이터 수집 |
| `collect_all_data_by_day(start, end)` | 날짜 범위 전체 수집 (에러 자동 재시도) |
| `collect_notice_by_NtceNo(list)` | 공고번호 리스트로 수집 (PK 방식) |
| `collect_company_by_bizno(list)` | 사업자번호 리스트로 수집 (PK 방식) |

**수집 우선순위:**
1. `start_date` + `end_date` 지정 → 해당 기간 수집
2. `year` 지정 → 해당 연도 전체 (01-01 ~ 12-31)
3. 둘 다 없음 → 기본값 (2001-01-01 ~ 2009-12-31)

### 2. ParamsBuilder (params_builder.py)

서비스별로 다른 API 요청 파라미터를 생성합니다.

**API 타입 매핑:**

| api_type | 서비스 | 날짜 필드 |
|----------|--------|-----------|
| `notice` | 입찰공고정보서비스 | `inqryBgnDt`, `inqryEndDt` |
| `company` | 사용자정보서비스 (업종정보) | `inqryBgnDt`, `inqryEndDt` |
| `pubData` | 공공데이터개방표준서비스 | 오퍼레이션별 상이 |

**pubData 서브타입:**

| sub_type | 오퍼레이션 | 날짜 필드 |
|----------|-----------|-----------|
| 1 | 낙찰정보 | `bidNtceBgnDt`, `bidNtceEndDt` |
| 2 | 개찰결과 | `opengBgnDt`, `opengEndDt` |
| 3 | 계약정보 | `cntrctCnclsBgnDate`, `cntrctCnclsEndDate` |

**bsnsDivCd (사업구분코드):**

| 코드 | 사업구분 |
|------|----------|
| 1 | 물품 |
| 2 | 외자 |
| 3 | 공사 |
| 5 | 용역 |

> **Note**: pubData API 호출 시 `bsnsDivCd` 파라미터로 사업구분을 지정합니다. 현재 기본값은 `3` (공사)입니다.

### 3. ApiClient (api_client.py)

HTTP 통신을 담당하며, 나라장터 API의 특수한 SSL 환경을 처리합니다.

**특징:**
- TLS 1.2 이하 강제 (나라장터 서버 호환성)
- 보안 레벨 낮춤 (`SECLEVEL=1`) - 구버전 Cipher 허용
- 연결 오류 시 자동 재시도 (10초 간격)
- JSON 디코드 실패 시 재시도

### 4. MissingCompanyCollector (missing_company_collector.py)

bid 수집 후 누락된 company를 증분 수집하는 모듈입니다.

**기능:**
- bid 4개 컬렉션에서 미동기화(`is_synced=False`) 문서의 `bidprcCorpBizrno` 추출
- company 컬렉션에 없는 사업자등록번호 식별
- 누락된 사업자등록번호로 조달업체기본정보 API 호출하여 수집

**사용:**
```python
from fetch_data.src.missing_company_collector import collect_missing_companies

# bid 수집 후 누락 company 수집
collected_count = collect_missing_companies()
```

**DAG 연동:**
- `data_collection_dag.py`에서 bid 4개 수집 완료 후 자동 실행
- FK 위반 방지를 위한 사전 수집

### 5. MongoWriter (mongo_writer.py)

MongoDB에 데이터를 저장하며 중복을 처리합니다.

**Upsert 로직:**
1. `insert_one()` 시도
2. `DuplicateKeyError` 발생 시 → `update_one()` 수행
3. `unique_fields` 기반 유니크 인덱스 자동 생성

**반환값:**
- `"insert"`: 새 문서 삽입됨
- `"update"`: 기존 문서 갱신됨
- `"error"`: 예외 발생

### 5. RecordWriter (record_writer.py)

수집 과정에서 발생한 에러 날짜 등을 파일로 기록합니다.

```
fetch_record/
└── {컬렉션명}/
    └── error_date.txt    # 에러 발생 날짜 목록
```

## 🔄 수집 플로우

### 날짜 기반 수집 (기본)

```
┌─────────────────────────────────────────────────────────────┐
│  DataCollector.execute()                                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  collect_all_data_by_day(start_date, end_date)              │
│  - 날짜 범위를 일(day) 단위로 순회                            │
│  - 에러 발생 날짜는 재시도 큐에 추가                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  collect_data_by_day(date)                                  │
│  1. ParamsBuilder로 요청 파라미터 생성                       │
│  2. ApiClient로 첫 페이지 요청 → totalCount 확인             │
│  3. 전체 페이지 순회하며 데이터 수집                          │
│  4. MongoWriter로 각 item upsert                            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  페이지네이션 처리                                           │
│  - numOfRows: 500 (한 페이지당 항목 수)                      │
│  - totalPages = ceil(totalCount / numOfRows)                │
│  - 각 페이지마다 API 요청 후 items 처리                       │
└─────────────────────────────────────────────────────────────┘
```

### PK 기반 수집 (결측 데이터 보완)

```python

# 특정 업체만 수집
collector.collect_company_by_bizno(["사업자번호1", "사업자번호2"])
```

### inqryDiv 파라미터와 대응 응답 필드

API별로 `inqryDiv` 값의 의미와 대응되는 응답 필드가 다릅니다.

| inqryDiv | 설명 | 대응 응답 필드 |
|----------|------|----------------|
| 1 | 등록일 기준 | `rgstDt` |
| 2 | 변경일 기준 | `chgDt` |
| 3 | 사업자등록번호 기준 | (필터 조건) |

#### 조달업체업종정보조회

| inqryDiv | 설명 | 대응 응답 필드 |

| 3 | 시스템변경일 기준 | `systmChgDt` |

> **주의**: `조달업체업종정보조회`의 `rgstDt`/`chgDt`는 **업종 자체의 등록/변경일** (업체가 해당 면허를 취득한 날짜)이며, 쿼리 날짜 파라미터와는 무관합니다. 쿼리 기준은 `systmRgstDt`/`systmChgDt` (나라장터 시스템에 데이터가 등록/변경된 일시)입니다.

## ⚠️ 주의사항

### 1. SSL/TLS 호환성

나라장터 API 서버는 최신 TLS를 지원하지 않아 특수 처리가 필요합니다:
- TLS 1.2 이하 강제
- 보안 레벨 낮춤 (`SECLEVEL=1`)

### 2. API 호출 제한

공공데이터 포털 API는 호출 횟수 제한이 있을 수 있습니다. 대량 수집 시 적절한 간격을 두고 진행하세요.

### 3. 에러 재시도

- 연결 오류/JSON 파싱 오류: 자동 재시도 (10초 간격)
- 날짜별 수집 실패: 전체 날짜 처리 후 재시도
- 재시도 횟수 제한 없음 (대부분 재시도 시 성공)

### 4. 중복 처리

- `unique_fields` 기반 유니크 인덱스로 중복 방지
- 동일 데이터 재수집 시 `update` 처리됨

## 🐛 트러블슈팅

### Q1. SSL 에러 발생

```
ssl.SSLError: [SSL: UNSUPPORTED_PROTOCOL]
```

**원인**: 나라장터 서버가 최신 TLS를 지원하지 않음
**해결**: `ApiClient`의 SSL 설정이 적용되었는지 확인

### Q2. JSON 디코드 에러 반복

**원인**: API 서버 일시적 장애 또는 네트워크 문제
**해결**: 자동 재시도 대기, 지속 시 수동 확인

### Q3. 특정 날짜 수집 반복 실패

**원인**: 해당 날짜에 데이터가 없거나 API 오류
**해결**: `fetch_record/{컬렉션명}/error_date.txt` 확인 후 수동 검증
